# ADR-0027：SQLite JDBC 驱动改为发行 jar 内嵌闭包

## 状态

已接受（细化 [ADR-0019](0019-network-forensics-sqlite-exception.md)：SQLite 例外范围与保留/分页策略不变，仅驱动分发方式演进；ADR-0019 决策历史保留）

## 背景

ADR-0019 决定 FR11 数据包取证使用本地 SQLite，驱动固定 `org.xerial:sqlite-jdbc:3.53.2.1` 并"由 TabooLib 运行时依赖加载器获取"。FR10 验收确立的运行期断网口径（HTTP/HTTPS 代理 `127.0.0.1:9`、TabooLib 运行时全部来自离线闭包）暴露了在线加载驱动的问题：离线服务器或首次取证时驱动不可得，取证会直接降级关闭；同时在线加载破坏"发行即完整"的可复现发行形态。

## 决策

SQLite JDBC `3.53.2.1` 作为发行 jar 内嵌闭包随包分发，不再依赖 TabooLib 在线下载。驱动加载失败（如 native 库不兼容）时行为不变：仅关闭数据库取证，聚合速率继续工作并打印中文 WARN。FR11 的取证范围、保留策略（60 天/4 GiB）、分页与脱敏边界均沿用 ADR-0019，不扩展为通用指标数据库。

## 理由

- 离线环境可用：驱动随发行 jar 完整到达，取证在首次启动即可工作，与 FR10 的断网验收口径一致。
- 发行可复现：版本在构建期锁定，运行期不引入外部下载面，规避在线加载失败的降级路径。
- 影响面最小：不改变 ADR-0019 的例外范围，也不引入新的存储形态。

## 影响

- 发行 jar 体积增加约数 MB（SQLite JDBC 含 native 库），属 FR11 取证能力的一部分。
- 驱动升级仍由构建脚本版本变量集中管理，随发行版本整体发布。
- `docs/specs/network-forensics.md` 与 PRD 中的分发描述同步为内嵌闭包事实。
