# ADR-0024：内嵌 Arthas 运行闭包改用官方 3.1.1

## 状态

已被 [ADR-0025](0025-arthas-dual-runtime-compatibility.md) 取代（原决策历史保留）

## 背景

FR14 需要把官方 Arthas 的最小运行闭包随单 jar 交付，避免事故现场再依赖外部下载。ADR-0022 指定的 4.3.4 不再是本项目采用的发行基线；维护者已确认使用官方仍可下载的 Arthas 3.1.1，以覆盖 3.0 代际兼容需求。

## 决策

构建脚本唯一版本变量固定为 `arthasVersion = "3.1.1"`，构建期解析官方 `com.taobao.arthas:arthas-packaging:3.1.1:bin@zip`。发行 jar 仍只内嵌 Core、Spy、Agent、Boot、必要配置、许可证、NOTICE 与 native 库；不展开原始 jar，不包含 client、math-game、文档和脚本。

ServerProbe 继续作为唯一 MCP 端点；官方 Arthas 自带 MCP 类不监听、不对外暴露。运行时仍按版本和 SHA-256 原子提取到插件数据目录，并使用隔离 ClassLoader 引导。

## 理由

- 3.1.1 是已确认可从官方渠道解析的版本，能避免构建期依赖不可获得版本。
- 保持原有最小运行闭包、单 jar 与运行期不联网策略，不扩大 FR14 的控制面或打包范围。
- 将版本集中在单一构建变量，后续升级仍可通过新增 ADR、替换版本和完整跨 JDK/平台验收完成。

## 后果

- FR14 尚未实现；实现、构建和验收必须以 3.1.1 的真实发行包、许可证、哈希和 API 行为为准。
- 所有 Arthas 适配、契约测试和 mc-testkit 诊断 fixture 都必须锁定 3.1.1，不能沿用 4.3.4 假设。
- 仅更换嵌入版本，不改变默认关闭、无第一方 OS Shell、可选鉴权和风险告警的既有边界。

## 备选方案

- **继续使用 4.3.4**：不符合已确认的官方可下载版本基线，否决。
- **复制 Arthas 源码进项目**：升级和许可证维护成本高，否决。
- **运行期下载 Arthas**：事故时受网络和下载可用性影响，否决。
