# ADR-0019：数据包取证使用受限 SQLite 例外

## 状态

已接受（细化 [ADR-0007](0007-local-file-storage-no-database.md)，不取代其对启动画像和指标历史的文件存储决策）；驱动分发方式已被 [ADR-0027](0027-sqlite-jdbc-embedded-runtime-closure.md) 细化为发行 jar 内嵌闭包

## 背景

FR11 需要按时间、玩家、IP、方向和包类型组合查询大量高频记录，并执行 60 天/4 GiB 的最早优先清理。JSON/JSONL 适合聚合历史，却无法在不全量扫描或建立额外索引的前提下可靠完成取证分页和保留；这属于 ADR-0007 未覆盖的包级证据场景。

## 决策

仅对 FR11 数据包取证内置本地 SQLite，驱动固定为 `org.xerial:sqlite-jdbc:3.53.2.1` 并由 TabooLib 运行时加载；其余持久化仍使用原有 JSON/JSONL 与存储 SPI。

## 理由

- SQLite 是嵌入式单文件存储，不引入外部数据库服务或网络依赖，能用索引和事务可靠支持查询、分页与滚动清理。
- 单写线程、有限队列和批量事务把磁盘 IO 隔离在 Netty/主线程之外，符合“不成为事故源”。
- 驱动加载失败时可明确关闭取证而不影响实时聚合，保留核心可观测性。

## 后果

- SQLite 只存网络包证据，不能作为通用指标、启动画像或第三方存储 SPI 的默认实现。
- 数据库 schema 需版本化；所有查询都要求时间范围并限制分页，完整 IP/载荷只向 Web 与同进程 FR8 API 提供。
- 60 天/4 GiB 为默认双上限，超限最早优先删除；不加密，依赖服务器文件权限。

## 备选方案

- **继续 JSONL 全量扫描**：高频查询与清理不可控，事故时会放大 IO，否决。
- **外部 MySQL/Redis**：增加部署与故障面，违背自包含目标，否决。
- **完全不保留载荷**：无法复现协议问题与排查攻击，不满足 FR11，否决。
