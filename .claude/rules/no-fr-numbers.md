# 需求编号禁止进入代码（强制）

> 适用于仓库内所有源代码、测试、配置文件与脚本。**需求编号只存在于文档。**

## 1. 规则

- 源码、测试、配置、脚本中**禁止出现需求编号**（形如 `FR-12`、`FR12` 这类「需求前缀 + 数字」的标识）。包括但不限于：
  - 注释（行注释、块注释、KDoc / Javadoc）
  - 标识符（类名、函数名、变量名、常量名）
  - 字符串字面量（日志文案、异常消息、验收结果文本）
  - 测试方法名与测试显示名
  - 文件名、目录名
- 需求编号**只能**出现在文档中：`docs/`（含 `docs/PRD.md`、`docs/API.md`、`docs/ARCHITECTURE.md`、`docs/adr/`、`docs/specs/`、`docs/wiki/`）、`CHANGELOG.md`、`README.md`、`.claude/rules/`。

## 2. 为什么

1. **编号会过期，代码不会**。需求表会重排、合并、撤销，编号一旦被写进代码，就变成一处无法随需求演进的引用——读者拿着代码里的编号去 PRD 找不到对应条目，或找到的是完全不同的需求。
2. **代码应当描述行为，不描述计划**。`// 校验玩家是否在线` 是代码的职责；`// FR-12 校验玩家是否在线` 把内部规划词汇泄漏进了产品。这与「提交信息禁止阶段性词语」同源：说的是「项目走到哪一步」而非「这段代码做什么」。
3. **编号会泄漏给用户**。字符串里的编号会进入日志、异常栈、E2E 验收结果文件，最终被服主看到。服主不知道也不需要知道需求编号。

## 3. 怎么写

- 需要说明来历或取舍时，**写决策本身**，不写编号：
  - ✅ `// 心跳独立线程发送：忙连接原先永不发 ping，对端会误判失联`
  - ✅ `// 见 docs/specs/provider-health.md`（引用文档路径，而非编号）
  - ❌ `// FR-30 心跳独立线程发送`
- 需要指向需求出处时，指向**文档路径或 ADR 文件名**，它是稳定的；不要指向编号。

## 4. 存量清理

- 本规则生效前已有的编号引用，随**所在代码的改动**顺手清理，不做一次性的全仓替换式提交（精准修改原则）。
- 例外：清理本身作为一次独立提交时，按文件逐个变更，不夹带功能改动。
