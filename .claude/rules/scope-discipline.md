# 范围纪律（防范围漂移 / 镀金）

> 依据 `docs/PRD.md` 的分期与 §4 FR 表。**只做当前阶段该做的，不提前做、不顺手做。**
> 已交付 v0.2.0：FR-01~FR-09；开发中待正式发版登记：FR-10~FR-14（验收证据齐备，见各 spec）。

## 1. 已交付范围（已落地，勿重复造轮子）

- **启动性能剖析（FR-01）**：端到端总时长、逐插件 onEnable、逐世界、生命周期分段、启动画像落盘与上次对比、慢启动告警；可选 premain agent（FR-01 子能力）提供逐插件/库下载/世界/配置/事件/命令精确耗时、多线程折叠栈采样、启动火焰图 + 嵌套时间线（`/probe flamegraph`）、HTTP/TCP 外呼监控（`/probe http`）。
- **运维指标（FR-02）**：JVM 全套、服务器 TPS/MSPT（多版本兼容 + Folia 全局 N/A）、世界区块/实体、网络 ping 分布、代理端 ping / 路由 / 每玩家 ping、运行期 CPU 采样归因（默认关闭）。
- **存储与聚合（FR-03）**：内存环形缓冲、本地文件落盘（启动画像 JSON + 指标历史 JSONL）、聚合（TPS 滑窗 / MSPT 分位 / GC 差分）。
- **呈现（FR-04）**：`/probe` 八子命令、Prometheus `/metrics`、Web 面板（默认关闭）、历史文件对比。
- **告警（FR-05）** / **全版本多平台骨架（FR-06）** / **方法级归因（FR-07，Incision，默认关闭）** / **开放接口（FR-08：只读 API + 存储 SPI + 静态门面）** / **业务对接 agent（FR-09：业务桥 + Provider + 事件上报，事故域隔离）**。

## 2. 后续阶段（禁提前实现 / 禁镀金）

以下属规划中 / 待登记，**当前不做、不留占位字段**：

- **FR-10~FR-14 的后续增量**：内置业务集成（MCE/AIS）新 Provider 或新业务域、网络取证白名单扩展、Folia region 能力扩展、Velocity 新版本适配、MCP 新工具——**未列入 PRD 的能力一律先经 brainstorming 确认**。
- 其他未被 PRD FR 表明确覆盖的未来能力。

一旦在代码 / 数据模型 / 契约里看到上述能力的提前实现或占位字段 → **删除，或停下来问**，不得镀金。

## 3. 不为未来预留空壳

- 不写"以后可能用"的抽象、配置项、接口、字段。需要时再加。
- 后续阶段能力到时按域新增包（如 `web/`、`incision/`），当前不留占位。

## 4. 越界先问

- 若某任务看起来需要某个后续阶段能力才能完成 → **停止并向用户确认**，不自行扩大范围。
- 简洁方案优先：实现远多于必要（如 200 行 vs 50 行）时重写。资深工程师会觉得过度复杂的，就是过度。
